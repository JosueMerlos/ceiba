## Objetivo

Se cumple todo el checklist de seguridad bloqueante para los pilotos: 2FA obligatorio donde corresponde, bloqueo progresivo, contraseñas contra HIBP, reset de contraseña seguro, la tabla completa de límites en dos capas, API keys funcionales y CSP endurecida.

## Alcance

**Incluye**

- 2FA TOTP (`rotp`) con QR y 8 códigos de respaldo; obligatorio para `org_owner`, `org_admin` y `PlatformStaff` (forzado en el siguiente login).
- Bloqueo progresivo por cuenta.
- HIBP (k-anonymity) al definir o cambiar la contraseña, con fallo abierto si el servicio no responde (registrado).
- Reset de contraseña: token de un uso (1 h), respuesta idéntica exista o no la cuenta, revocación de sesiones al cambiarla.
- Rack::Attack: tabla completa (reglas 4, 5, 6, 7 y 9).
- `rate_limit` de Rails por `user_id` y `api_key_id`.
- API keys: creación (se muestra una vez), scopes, rotación, revocación, `Principal::ApiKey` con Pundit; UI en el panel para `org_owner` y `org_admin`.
- CSP del panel en modo enforce (con nonces o hashes).
- Revisión con `brakeman` sin advertencias ignoradas sin justificar.
- Test de NAT.

## Criterios de aceptación

1. **Dado** un `org_admin` sin 2FA, **cuando** inicia sesión, **entonces** se le exige configurarlo antes de acceder.
2. **Dado** un código de respaldo usado, **cuando** se reutiliza, **entonces** se rechaza.
3. **Dado** 5 contraseñas incorrectas, **cuando** se intenta la sexta, **entonces** la cuenta queda bloqueada temporalmente aunque cambie la IP.
4. **Dado** `password123456` (presente en filtraciones), **cuando** se define, **entonces** se rechaza.
5. **Dado** 6 usuarios distintos tras la misma IP haciendo un uso normal, **cuando** operan durante 5 min, **entonces** ninguno recibe `429`.
6. **Dado** una API key con `read:appointments`, **cuando** intenta crear una cita, **entonces** recibe `403`; al revocarla, la siguiente request recibe `401`.
7. **Dado** el panel con CSP en modo enforce, **cuando** corre la suite E2E, **entonces** pasa sin violaciones registradas.
