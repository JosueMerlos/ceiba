## Objetivo

Un operador de plataforma da de alta una organización completa desde un back-office en minutos. El dueño recibe una invitación, activa su cuenta con 2FA e invita a su staff con los roles correctos. Todo el acceso del operador a los datos de un tenant queda auditado.

## Alcance

**Incluye**

- `platform_staff` (separado de `users`), login en `/platform` con 2FA obligatorio.
- Back-office mínimo (rutas `/platform/*` en el panel o una sección aislada): listar organizaciones, provisionar (formulario sobre `ProvisionOrganization`), activar o desactivar módulos por empresa, suspender una organización.
- `platform_access_grants` (just-in-time: motivo, caducidad) para ver datos de un tenant; todo auditado con `actor_type = platform_staff`.
- Sidekiq Web UI y Flipper UI montadas solo para `PlatformStaff`.
- Invitaciones: token firmado (7 días), reenvío, revocación; aceptación con contraseña y aviso de privacidad. Regla: invita quien tiene un rol de gestión en el alcance de destino.
- UI del panel para usuarios y roles: invitar, cambiar rol, quitar acceso, transferir la propiedad (solo `org_owner`).
- Seeds: un `PlatformStaff` de desarrollo.

## Tareas

- [ ] **Rojo → Verde:** modelo `PlatformStaff`, su login y su 2FA (reutilizando las piezas de `identity`).
- [ ] **Rojo → Verde:** grants just-in-time (sin grant → no ve datos; grant expirado → `403`).
- [ ] **Rojo → Verde:** invitaciones (permisos de quién invita a qué rol, expiración, revocación).
- [ ] **Rojo → Verde:** transferencia de propiedad (siempre queda exactamente un `org_owner`).
- [ ] Back-office UI + E2E de alta completa.

## Criterios de aceptación

1. **Dado** un operador, **cuando** provisiona una organización desde el back-office, **entonces** se crean la organización, la empresa, la sucursal, el módulo de citas activo y la invitación al dueño.
2. **Dado** un operador sin un grant vigente, **cuando** intenta ver los clientes de una organización, **entonces** recibe `403`; con un grant, puede verlos y queda auditado.
3. **Dado** un `branch_manager`, **cuando** invita a alguien como `company_manager`, **entonces** recibe `403`.
4. **Dado** una invitación de hace 8 días, **cuando** se abre, **entonces** está expirada y se puede reenviar.
5. **Dado** una transferencia de propiedad, **cuando** termina, **entonces** el nuevo dueño es `org_owner`, el anterior pasa a `org_admin` y nunca hay cero ni dos dueños.
6. **Dado** un usuario normal, **cuando** visita `/platform` o la Sidekiq UI, **entonces** recibe `404`.
