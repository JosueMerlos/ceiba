## Objetivo

El panel permite iniciar sesión, elegir la organización, la empresa y la sucursal, y muestra un layout con navegación construida **solo** a partir de `/api/v1/me`: módulos activos y permisos. Cada módulo se carga de forma lazy. Los textos están en i18n `es-NI`, y un E2E con Playwright cubre el flujo.

## Contexto

- Cierra F0 por el lado del frontend: el "walking skeleton" queda completo de punta a punta.
- El branding por empresa llega en M2.04, pero los tokens CSS se definen aquí para no rehacer los estilos.

## Alcance

**Incluye**

- Decisión y configuración del router (React Router en modo data o TanStack Router), documentada como ADR breve si se elige TanStack Router.
- `packages/ui`: Tailwind + shadcn/ui inicial (botón, input, form, dialog, toast, dropdown, layout), tokens CSS (`--color-*`, `--brand-*` con defaults).
- `packages/i18n`: i18next `es-NI`, formatos con `Intl`.
- Panel: providers (QueryClient, i18n, router), página de login, manejo de `401`, `403`, `404` y `409`, selector de contexto (oculto si solo hay una opción), layout con navegación filtrada por permisos.
- Registro de módulos del front (`modules/registry.ts`) con el placeholder de `appointments` (rutas lazy).
- `<Can>` / `useCan()`.
- Envío del token CSRF en las mutaciones desde `api-client`.
- Playwright configurado sobre Docker Compose con un E2E: login → contexto → navegación.
- `apps/booking`: estructura base (sin funcionalidad), con un presupuesto de tamaño de bundle medido en CI.

**No incluye**

- Pantallas de catálogo y agenda → F2. Branding dinámico → M2.04.

## Criterios de aceptación

1. **Dado** un usuario de una sola organización, empresa y sucursal, **cuando** inicia sesión, **entonces** llega directo al layout sin ver el selector.
2. **Dado** un usuario con dos organizaciones, **cuando** cambia de una a otra, **entonces** la caché de queries se invalida y no se muestran datos de la anterior.
3. **Dado** una empresa con `appointments` inactivo, **cuando** se carga el panel, **entonces** el menú no muestra "Agenda" y la URL `/agenda` muestra "no encontrado".
4. **Dado** un `receptionist`, **cuando** ve el layout, **entonces** solo aparecen los items de navegación cuyos permisos tiene.
5. **Dado** una sesión expirada, **cuando** cualquier request devuelve `401`, **entonces** se redirige al login conservando la ruta de retorno.
6. **Dado** el build de producción, **cuando** se inspecciona, **entonces** el módulo `appointments` está en un chunk separado.
7. **Dado** el E2E, **cuando** corre en CI, **entonces** pasa: login → contexto → navegación.
