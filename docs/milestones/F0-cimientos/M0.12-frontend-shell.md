## Objetivo

El panel permite iniciar sesión, elegir la organización, la empresa y la sucursal, y muestra un layout con navegación construida **solo** a partir de `/api/v1/me`: módulos activos y permisos. Cada módulo se carga de forma lazy. Los textos están en i18n `es-NI`, y un E2E con Playwright cubre el flujo.

## Contexto

- Cierra F0 por el lado del frontend: el "walking skeleton" queda completo de punta a punta.
- El branding por empresa llega en M2.04, pero los tokens CSS se definen aquí para no rehacer los estilos.

## Criterios de aceptación

1. **Dado** un usuario de una sola organización, empresa y sucursal, **cuando** inicia sesión, **entonces** llega directo al layout sin ver el selector.
2. **Dado** un usuario con dos organizaciones, **cuando** cambia de una a otra, **entonces** la caché de queries se invalida y no se muestran datos de la anterior.
3. **Dado** una empresa con `appointments` inactivo, **cuando** se carga el panel, **entonces** el menú no muestra "Agenda" y la URL `/agenda` muestra "no encontrado".
4. **Dado** un `receptionist`, **cuando** ve el layout, **entonces** solo aparecen los items de navegación cuyos permisos tiene.
5. **Dado** una sesión expirada, **cuando** cualquier request devuelve `401`, **entonces** se redirige al login conservando la ruta de retorno.
6. **Dado** el build de producción, **cuando** se inspecciona, **entonces** el módulo `appointments` está en un chunk separado.
7. **Dado** el E2E, **cuando** corre en CI, **entonces** pasa: login → contexto → navegación.

### Qué se hizo

- **Router:** prueba corta (build de Vite con ruta lazy + loader en ambos): mismo tamaño y ambos parten el módulo. **React Router 8.5.1 en modo data**: el criterio decisivo es montar rutas desde `/me` en tiempo de ejecución (`useRoutes`). Sin ADR (solo se pide si se elige TanStack Router).
- **`packages/ui`** (Tailwind 4 + shadcn/ui, solo lo que usa el hito: botón, input, label, form, dialog, dropdown, toast/Sonner, layout) con **tokens en tres capas** y nombres semánticos de shadcn/ui, `--brand-*` como capa que sobrescribirá M2.04 → **[ADR-0031](../../adr/0031-tokens-de-diseno-en-tres-capas.md)**. Identidad: paleta del árbol (dosel verde, fibra de kapok, acento sacuanjoche), Bricolage Grotesque + Figtree autoalojadas, anillos de crecimiento como único gesto decorativo (login).
- **`packages/i18n`:** i18next es-NI con catálogo tipado, formatos `Intl` (zona de la sucursal obligatoria; "US$" para el dólar). Regla `i18next/no-literal-string` en `@ceiba/config`.
- **`@ceiba/api-client`:** `X-CSRF-Token` automático en mutaciones (token en memoria, capturado del login y de `GET /auth/session`), hooks base de TanStack Query. Contrato y cliente **sin drift** (`bin/ci api-contract` ok).
- **Panel:** providers, login (react-hook-form + zod, errores asociados al campo), manejo global de 401/403/404/409, selector de contexto, layout con navegación filtrada por `/me`, menú de cuenta (cerrar sesión / en todos los dispositivos con diálogo de confirmación), registro de módulos con `appointments` placeholder lazy, `<Can>`/`useCan`.
- **`apps/booking`:** estructura base con tokens e i18n y **presupuesto de 150 KiB gzip de JS crítico** (hoy 85.3 KiB) medido por `frontend/bin/ci-bundle`.
- **E2E:** Playwright 1.65.0 sobre Compose (servicio `e2e`, imagen propia fijada, red compartida con el proxy), 7 tests. `bin/ci e2e` / `make e2e`; job `e2e` de `ci.yml` solo en `main`.

### Desvíos y decisiones

| Desvío / decisión | Motivo |
| --- | --- |
| `--accent` conserva el rol de shadcn y el acento de marca es `--highlight` | Un acento vistoso de empresa teñiría cada menú (ADR-0031) |
| Un chunk por módulo: `assets/module-<clave>-<hash>.js` (`chunkFileNames`), con las páginas en `modules/<clave>/routes.tsx` y el manifiesto en `index.tsx` | 08 decía `index.ts` y `routes/`; con `lazyPage()` JSX y un único `import("./routes")` el módulo entero queda en un chunk |
| Las rutas llevan su `permission` y `routesFor(me)` las filtra | Un receptionist no puede abrir `/agenda/summary` por URL: lo que `/me` no ofrece no se monta |
| `eslint-plugin-i18next` con `include` de atributos de texto | En `jsx-only` revisaba `data-slot`, `aria-hidden`… y era inusable |
| `@ceiba/e2e` expone el script `e2e` (no `test`) | `pnpm -r test` de `frontend-test` lo habría ejecutado sin entorno |
| El servicio `e2e` usa `network_mode: service:proxy` | Entra por `localhost:8080`; evita tocar `config.hosts` de Rails y mantiene Origin/Host reales |
| Hooks de logout pasan `X-CSRF-Token: ""` | El contrato lo declara obligatorio; el middleware lo reemplaza con el token real |
| `describeError` busca `errors:code.<code>` con `defaultValue` | Un `code` sin traducción es normal y no debe disparar el aviso de clave inexistente |
| Un usuario con 403 en `/me` (p. ej. organización suspendida elegida por la cookie) ve la pantalla de permiso con «Cerrar sesión» | Sin `/me` no hay layout ni selector; es la salida mínima |
| `bin/ci` incluye `e2e` y `frontend-bundle` en las etapas por defecto | Mismos pasos que CI; el E2E tarda ~1 min y reinicia el entorno |
