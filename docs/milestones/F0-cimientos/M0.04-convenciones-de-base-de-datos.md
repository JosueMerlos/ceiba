## Objetivo

Toda tabla nueva usa UUIDv7 por defecto, y una sola línea (`create_tenant_table`) crea una tabla tenant con `organization_id`, FK compuesta, índices y política RLS deshabilitada. CI rechaza migraciones peligrosas.

## Contexto

- Las convenciones de BD son las más caras de cambiar después: cambiar el tipo de PK o añadir `organization_id` con datos reales es un proyecto entero.
- Este hito crea las **herramientas**; las tablas reales empiezan en M0.05.

## Alcance

**Incluye**

- `primary_key_type: :uuid` en los generadores y `default: -> { "uuidv7()" }`.
- `structure.sql` en lugar de `schema.rb`.
- Extensiones: `btree_gist`, `citext`, `pg_stat_statements` (esta última solo donde aplique).
- Helpers de migración: `create_tenant_table`, `t.tenant_reference`, `enable_tenant_rls(table)` (usado en M4.03), registro de tablas tenant.
- Roles de BD de desarrollo: `app_owner` (migraciones) y `app_user` (aplicación, sin dueño de tablas, sin `BYPASSRLS`). Configuración de `database.yml` para usar cada uno.
- `strong_migrations` en CI.
- i18n base del backend: `rails-i18n`, `default_locale = :"es-NI"`, `available_locales`.
- `config.time_zone = "UTC"`.

**No incluye**

- Tablas de dominio → M0.05+. Activar RLS → M4.03.

## Diseño

Ver [09 §Tablas tenant](../../architecture/09-data-conventions.md#tablas-tenant). `tenant_reference :company` genera la columna, la FK compuesta `(organization_id, company_id) → companies(organization_id, id)` y el índice `(organization_id, company_id)`.

La política RLS se crea con `CREATE POLICY` pero **sin** `ENABLE ROW LEVEL SECURITY`.

## Criterios de aceptación

1. **Dado** `rails g model Foo`, **cuando** se migra, **entonces** `foos.id` es `uuid` con default `uuidv7()`.
2. **Dado** una tabla creada con `create_tenant_table`, **cuando** se inspecciona, **entonces** tiene `organization_id NOT NULL`, la FK a `organizations`, `UNIQUE(organization_id, id)` y una política en `pg_policies` con RLS **deshabilitado**.
3. **Dado** dos tablas tenant relacionadas con `tenant_reference`, **cuando** se inserta una hija con un `organization_id` distinto al de su padre, **entonces** PostgreSQL rechaza la inserción.
4. **Dado** una migración que agrega un índice sin `algorithm: :concurrently`, **cuando** corre CI, **entonces** strong_migrations la bloquea.
5. **Dado** la aplicación en ejecución, **cuando** se consulta `current_user` en la BD, **entonces** es `app_user`, que no es dueño de las tablas.
6. **Dado** `db/structure.sql`, **cuando** se carga en una BD vacía, **entonces** incluye extensiones, políticas y FKs compuestas.
