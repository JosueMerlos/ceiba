## Objetivo

Existe un endpoint real (`GET /api/v1/organizations/:id`, temporalmente sin autenticación en dev) documentado en OpenAPI generado por rswag. El frontend lo consume con un cliente TypeScript **generado**. Los errores salen como problem+json y CI falla si el contrato y el cliente divergen.

## Contexto

- Todo lo que viene (auth, `/me`, citas) produce endpoints. Si las convenciones (errores, paginación, serializers) no existen antes, cada endpoint inventa la suya.
- Se adelantó respecto al plan original porque M0.07 y M0.09 ya necesitan el formato de errores y el cliente.

## Alcance

**Incluye**

- rswag (specs → `openapi/v1.yaml`), Swagger UI en `/api/docs` (dev y staging).
- `ApplicationController` de la API: rescates centralizados → problem+json (400, 404, 409, 422, 500), `request_id` en la respuesta.
- Alba como serializer; convención de un serializer por representación.
- Paginación por cursor genérica (`Api::Pagination::Cursor`) basada en UUIDv7.
- `packages/api-client`: `openapi-typescript` + `openapi-fetch`, `ApiError` tipado, base para hooks de TanStack Query.
- Script `pnpm api:generate` y check de drift en CI.
- Endpoint de ejemplo `GET /api/v1/organizations/:id` (se protegerá en M0.07/M0.08).

**No incluye**

- Autenticación y CSRF → M0.07. `Idempotency-Key` → M0.11.

## Criterios de aceptación

1. **Dado** un id inexistente, **cuando** se pide `GET /api/v1/organizations/:id`, **entonces** responde `404` con `Content-Type: application/problem+json` y los campos `type`, `title`, `status`, `code` y `request_id`.
2. **Dado** una validación fallida en un endpoint de prueba, **cuando** responde, **entonces** es `422` con `errors[]` por campo.
3. **Dado** una excepción no controlada, **cuando** ocurre, **entonces** responde `500` problem+json **sin** stacktrace ni detalles internos.
4. **Dado** un cambio en un serializer sin regenerar el contrato, **cuando** corre CI, **entonces** falla el check de drift.
5. **Dado** el cliente generado, **cuando** el código TS accede a un campo inexistente de la respuesta, **entonces** `tsc` falla.
6. **Dado** 120 registros, **cuando** se pagina con `limit=50`, **entonces** hay 3 páginas sin duplicados ni omisiones, aunque se inserten registros nuevos entre páginas.

### Qué se hizo

- **Errores problem+json** (`Api::Problem`, `Api::ErrorRegistry`, `Api::ErrorHandling`, `Api::ExceptionsApp`): 400, 404, 409, 422 y 500 con `type`/`title`/`status`/`code`/`instance`/`request_id`; `errors[]` por campo; registro de errores de dominio → `code` (único) con los de Active Record, parámetros, paginación y tenancy (`ProvisioningFailed`, `InconsistentContext`). El 500 no lleva ningún detalle, tampoco en desarrollo (`consider_all_requests_local = false` en development y test). Tabla de `code` en [07](../../architecture/07-api-contract.md#errores-applicationproblemjson-rfc-9457).
- **Paginación por cursor** `Api::Pagination::Cursor` (+ `render_page`): orden por id UUIDv7, `limit + 1` para `has_more`, cursor firmado con `MessageVerifier` (URL-safe, propósito propio), `limit` 1–100.
- **Alba 4.0.3** (`Api::Serializer`, tipo `:iso8601`) y **endpoint de ejemplo** `GET /api/v1/organizations/:id` en el pack `platform/tenancy` (controlador `Api::V1::Tenancy::OrganizationsController`), temporalmente sin autenticación y solo con `config.x.api.open_organization_endpoint` (development/test).
- **rswag 2.17.0** → `backend/openapi/v1.yaml` determinista (`Openapi::Formatter`/`Normalizer`, `bin/rails openapi:generate`), componentes `$ref` `Problem`, `ValidationProblem`, `FieldError`, `PageInfo`, `Organization`; **Swagger UI** en `/api/docs` solo con `Api::Docs.enabled?`.
- **`frontend/packages/api-client`** (`@ceiba/api-client`): `openapi-typescript` 7.13.0 + `openapi-fetch` 0.17.0, `createApiClient` (`credentials: "include"`), `ApiError` tipado y `unwrap` (base para los `queryFn` de TanStack Query); tests con Vitest 5.1 + MSW 3.0.4 y `tsc` real sobre fixtures. `pnpm api:generate` y `bin/api-generate`.
- **Check de drift:** `infra/scripts/check-api-contract.sh` (+ `_test.sh`), etapa `api-contract` en `bin/ci`, job `api-contract` en `ci.yml` y check requerido en `branch-protection.sh`; `backend/bin/ci-openapi` y `frontend/bin/ci-api-client`.
- Infraestructura tocada (acotada, para facilitar el merge): `compose.yaml` (volumen `api_client_node_modules` y montaje de solo lectura de `backend/openapi`), `frontend.Dockerfile` (directorios de montaje), `Gemfile`/`Gemfile.lock` (alba, rswag-api/ui/specs, ostruct), `pnpm-lock.yaml`, `bin/ci`, `ci.yml`, `branch-protection.sh`, `.rubocop.yml` (spec/api), `config/application.rb` (`exceptions_app`, `lib/openapi` fuera del autoload), `routes.rb` (v1 + docs), `config/environments/{development,test}.rb`.
- Docs: [07](../../architecture/07-api-contract.md) (reescrito con lo implementado), [02](../../architecture/02-modular-monolith.md), [03](../../architecture/03-multi-tenancy.md), [08](../../architecture/08-frontend.md), [10](../../architecture/10-infrastructure.md), [12](../../architecture/12-testing-strategy.md) y el README.

### Desvíos de la doc

| Desvío | Motivo |
| --- | --- |
| `type` del problema es un URN (`urn:ceiba:error:<code>`), no `https://docs.<dominio>/errors/...` | Aún no hay dominio de documentación; un URL inexistente sería una referencia colgante. RFC 9457 admite cualquier URI; se cambia en `Api::Problem#to_h` |
| El controlador de ejemplo vive en `platform/tenancy` (`Api::V1::Tenancy::OrganizationsController`) | Packwerk impide usar `Tenancy::Organization` (privado) desde fuera del pack; ubicarlo en el pack evita ampliar la API pública de tenancy (`public_api_spec`) |
| El endpoint de ejemplo solo existe con un flag (`open_organization_endpoint`, development/test) y en producción responde 404 | Sin autenticación (M0.07) ni autorización (M0.08) expondría cualquier organización. El flag se elimina al protegerlo |
| `consider_all_requests_local = false` en development y test | Con `true`, Rails responde una página/JSON de depuración **con stacktrace** a los errores que no pasan por un controlador, incumpliendo "500 sin detalles"; además esquiva `exceptions_app`. El detalle sigue en el log |
| `TenantMismatch`/`TenantIsImmutable` no tienen `code` propio: 500 genérico | Solo se lanzan ante un bug del servidor (07: "500: solo bugs") |
| Esquemas con `required` + `additionalProperties: false` escritos a mano en lugar de `openapi_strict_schema_validation` | El modo estricto de rswag vuelve obligatorios todos los campos y rompe los opcionales (`detail`, `errors`) |
| OpenAPI 3.0.3, no 3.1 | rswag valida las respuestas con `json-schema`, que no entiende `type: [x, "null"]`; 3.0 usa `nullable` |
| Un formateador propio (`Openapi::Formatter`) en lugar de `rswag:specs:swaggerize` | Hace falta salida canónica (claves ordenadas, sin símbolos YAML ni plegado de líneas) y corregir que rswag copia el `produces` de la operación a todas sus respuestas (un 200 saldría también como `problem+json`) |
| `packages/api-client` usa `typescript@6.0.3` | `openapi-typescript` 7.13 usa `ts.factory`, que TS 7 no expone (`createKeywordTypeNode` de `undefined`). Mismo patrón que `packages/config` ([10](../../architecture/10-infrastructure.md)) |
| `limit` inválido → 400 (no se recorta) | Un recorte silencioso esconde errores del cliente; el contrato lo documenta |
| El cursor está firmado pero no cifrado | El requisito era "opaco firmado"; el contenido (un id) no es secreto |
| `gem "ostruct"` explícita | `rswag-ui` la usa y en Ruby 3.4 avisa en cada arranque (dejará de ser gema por defecto en 4.0) |
| El soporte `spec/support/api_probes.rb` dibuja rutas de sonda solo durante el grupo de specs que lo pide | Los criterios 2, 3 y 6 exigen "un endpoint de prueba" que no debe existir en la aplicación real |

### Limitaciones y pendiente de verificar con el remoto

- El job `api-contract` de `ci.yml` y su check requerido en `branch-protection.sh` están como archivos (validados con `actionlint` y `bin/ci api-contract`); falta verlos correr en GitHub Actions (instalación de `postgresql-client-18`, cachés, tiempos).
- Dependabot: `packages/api-client` fija `typescript@6.0.3`; el `ignore` existente de `dependabot.yml` ya cubre ese pin, pero hay que confirmar su comportamiento con el remoto.
- El endpoint de ejemplo es **temporal**: M0.07/M0.08 lo protegen y eliminan `open_organization_endpoint`. `ValidationProblem` y `PageInfo` están en el contrato pero ningún endpoint los referencia todavía (el primer listado con `render_page` lo hará).
- Los hooks de TanStack Query no se crearon (la librería es de M0.12); `unwrap` es la base. El token CSRF y `Idempotency-Key` quedan para M0.07 y M0.11.
- `pnpm audit` sigue informando 1 vulnerabilidad moderada heredada de M0.02 (`minimatch`), por debajo del umbral.
- Con `consider_all_requests_local = false`, en desarrollo no hay página de depuración de Rails para los errores previos a un controlador: se depura con el log y el `request_id`.
