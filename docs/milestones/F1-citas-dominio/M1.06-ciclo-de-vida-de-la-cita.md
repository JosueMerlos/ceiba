## Objetivo

Las citas solo cambian de estado por transiciones válidas, autorizadas y concurrentemente seguras. Reprogramar crea una cita nueva enlazada a la anterior. Cada cambio deja evento y auditoría, y vía API se pueden listar las citas de una sucursal en un rango para la agenda.

## Alcance

**Incluye**

- `Appointments::Transitions` (tabla de transiciones + permiso requerido + precondiciones temporales).
- `Appointments::Transition` (bloqueo, `UPDATE … WHERE status IN (…)`, verificación de filas afectadas, evento y auditoría).
- `Appointments::Reschedule` (bloqueo de la original → `rescheduled` → `Book` con `rescheduled_from_id`), todo en una transacción.
- `Appointments::Cancel` con motivo y `cancelled_by`; la ventana de cancelación aplica solo a los clientes (M3.04).
- Endpoints: `POST …/appointments/:id/{confirm,check_in,complete,no_show,cancel,reschedule}`; `GET …/appointments?branch_id&from&to&professional_id` (rango máximo de 31 días, sin paginar para la agenda, con límite duro).
- `lock_version` para ediciones de notas.
- Eventos `confirmed`, `rescheduled`, `cancelled`, `completed`, `no_show`.

## Tareas

- [ ] **Rojo → Verde:** tabla de transiciones (todas las válidas pasan y todas las inválidas dan `409 appointments.invalid_transition`).
- [ ] **Rojo → Verde:** precondiciones temporales (`no_show` antes del inicio → `409`).
- [ ] **Rojo → Verde:** reprogramar (encadenamiento, la original queda `rescheduled`, el nuevo hueco se valida con `Book`).
- [ ] **Rojo → Verde:** doble reprogramación concurrente → 1 éxito y un `409`.
- [ ] **Rojo → Verde:** permisos (el profesional solo marca sus propias citas).
- [ ] Listado para la agenda + rswag.

## Criterios de aceptación

1. **Dado** una cita `completed`, **cuando** se intenta cancelar, **entonces** se recibe `409 appointments.invalid_transition`.
2. **Dado** dos reprogramaciones simultáneas de la misma cita, **cuando** se procesan, **entonces** existe una sola cita nueva y la otra request recibe `409`.
3. **Dado** una reprogramación a un hueco ocupado, **cuando** se procesa, **entonces** se recibe `409` y la cita original **sigue** `scheduled` (rollback completo).
4. **Dado** un `professional`, **cuando** marca `no_show` una cita de otro profesional, **entonces** se recibe `403`.
5. **Dado** cualquier transición exitosa, **cuando** se inspecciona, **entonces** hay un evento del tipo correspondiente y un registro de auditoría con el estado anterior y el nuevo.
6. **Dado** una semana con 200 citas en una sucursal, **cuando** se pide el listado de la agenda, **entonces** responde en < 150 ms en dev con un número constante de consultas.
